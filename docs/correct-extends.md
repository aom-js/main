# Правильное наследование

> **Черновик автора — исторический документ:** мысли на момент проектирования, а не описание текущего кода. Наследование сейчас — [`packages/core/readme.md`](../packages/core/readme.md); расхождения заметок с кодом — [`architecture.md`](architecture.md#расхождения-с-историческими-заметками).

В текущей реализации есть один недостаток, который может себя проявить в будущих случаях. А именно то, что при управляемом наследовании через декоратор перенос родительских декораторов происходит в конец дочернего списка callstack. Что само собой приведет к нарушению целостности логики, которая закладывается при их определении.

Применение unshift при переносе чисто технически возможно по той причине, что я могу предварительно сделать reverse процедуру. Однако это всё-равно не решает главной задачи с корректной последовательностью в ситуациях, когда, например, наследуемые декорированные методы, например, `OnInstance` попадают в конец, хотя должны быть выполнены в начале, и создать правильную цепочку установок значений.

В общем, здесь следует подумать. Да и вообще, у меня механика наследований давно напрашивалась на рефакторинг.

То есть в целом следует реорганизовать структуру цепочек вызовов, чтобы я мог их ставить в том порядке, в котором хочу.
