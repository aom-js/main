# Cookbook: рабочие правила и рецепты `@aom`

Здесь собираются **практические** ответы на вопрос «как правильно написать вот это» — с рабочими примерами, объяснением, почему именно так, и указанием, где тот же код исполняется тестом.

Чем это отличается от остальной документации:

| Файл                         | Что в нём                                                                |
| ---------------------------- | ------------------------------------------------------------------------ |
| `packages/<пакет>/readme.md` | справочник: что делает каждый декоратор, какие поля у каждого класса     |
| `docs/architecture.md`       | как устроено ядро целиком: пакеты, зависимости, фазы, порядок исполнения |
| `docs/<тема>.md`             | исторические заметки автора на момент проектирования                     |
| **`docs/cookbook/`**         | **как писать прикладной код и на чём тут спотыкаются**                   |

## Правила ведения

1. **Каждый пример должен исполняться тестом.** Рецепт без теста протухает за пару месяцев и начинает врать. В конце каждого рецепта — ссылка на тест-файл, в котором лежит тот же код; в самом тесте — комментарий-обратная ссылка на рецепт.
2. **Сначала рабочий код, потом объяснение.** Рецепт читают, когда что-то не получается, а не для общего развития.
3. **Антипримеры обязательны.** Если приём перестал работать или работает не так, как кажется, — показать «было / стало», а не только правильный вариант.
4. **Никаких повторов справочника.** Список аргументов декоратора — в readme пакета; сюда попадает только то, что из сигнатуры не видно.
5. Один рецепт — один файл, имя по теме (`this-and-instances.md`, а не `router-2.md`).
