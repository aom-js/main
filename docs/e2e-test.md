# E2E тестирование

> **Черновик автора — исторический документ:** мысли на момент проектирования, а не описание текущего кода. Как ядро помогает проверять цепочки маршрутов приложения — [`testing.md`](testing.md); расхождения заметок с кодом — [`architecture.md`](architecture.md#расхождения-с-историческими-заметками).

Хочется сделать тестирование, которое будет нормально и предсказуемо себя вести, а также позволит составлять сложные сценарии. При этом чисто технически для организации процесса тестирования у меня почти всё нужное есть.

Я могу извлечь роутер и разложить его на маршруты.
Я могу обнаружить все типы, которые могут вернуться в том или ином методе.
Я хочу иметь возможность переключать контекст и прокидывать данные между разными сессиями.
Я хочу составлять типовые сценарии, которые будут позволять создавать данные по определённому паттерну, и прогонять их через контекстный маршрут, где будут меняться роли, организации, пользователи.

То есть, как это должно выглядеть?

В идеале это должны быть именованные заготовки, которые будут выполнять типовые сценарии:

- регистрация организации
- приглашение пользователей
- создание партнерства
- запрос и выдача полномочий
- создание и модераций запроса
- создание и обработка откликов
- и так далее

При этом идеально будет сочетать механики пересекающихся контекстов через поиск совпадений на базе тех SQL запросов, которые генерируются в соответствующих модулях общего кода. То есть тестирование должно использовать те же механики, которые определяют подходящие критерии в общих программных логиках исходного кода.
